# Render: личный сайт с одним аккаунтом

Это инструкция размещения подготовленного кода. Само её наличие не означает, что сервис уже создан или сайт закрыт.

## 1. Сохрани старые отметки

Пока работает прежний сайт GitHub Pages, открой его в браузере, где учился: **Настройки → Скачать progress.sqlite**. Если пользовался с нескольких устройств, сохрани нужную копию каждого. Новый сервер не может прочитать данные старого браузерного сайта автоматически.

## 2. Проверь GitHub

Открой свой репозиторий `eremeev-sa/my_learn_site` (или `dev-growth`, если уже переименовал). Выбери **main**. В списке должны быть `server/`, `render.yaml`, `login.html` и эта инструкция. В Actions проверка **Check private learning server** должна завершиться зелёной галочкой.

## 3. Подключи Render

1. Открой **https://dashboard.render.com/** и зарегистрируйся/войди.
2. Нажми **New + → Blueprint** (может называться «New Blueprint Instance»).
3. Подключи GitHub и разреши Render доступ к этому репозиторию. Для приватного репозитория разреши его явно.
4. Выбери репозиторий и ветку **main**, путь Blueprint — **render.yaml**.
5. Дай набору ресурсов имя, например **dev-growth**.

## 4. Задай вход и проверь стоимость

Blueprint создаёт Web Service **dev-growth** с тарифом **Starter** и постоянным диском **1 GB**. Render покажет текущую стоимость сервиса и диска **до создания**. Это платное размещение; бесплатный сервис без постоянного диска не сохраняет SQLite надёжно при перезапуске/перевыкладке. Если стоимость не подходит, не подтверждай создание.

В поле **OWNER_PASSWORD** введи свой пароль (12–200 символов). Можно использовать ранее выбранный пароль; я не включаю его в публичную инструкцию или код. **OWNER_USERNAME** уже задан как `Eremeev-SA`. Не вводи пароль в `render.yaml`, GitHub Issues, README или сообщения сборки.

Остальные значения уже подготовлены:

| Параметр | Значение |
| --- | --- |
| Runtime | Node |
| Node | 24 |
| Build Command | `npm run build` |
| Start Command | `npm start` |
| Health Check | `/healthz` |
| NODE_ENV | `production` |
| DATA_DIR | `/var/data` |
| Disk Mount Path | `/var/data` |

Подтверди **Deploy Blueprint / Create resources** после проверки цены. В этой инструкции не создаются покупки автоматически.

## 5. Дождись публикации и войди

Открой созданный Web Service → **Events**. Дождись **Live / Deploy succeeded**. Во вкладке Logs ожидается `Dev Growth server is ready`. Реальные пароли/сессии сервер в лог не выводит.

Адрес появится в верхней части страницы сервиса, например `https://dev-growth-xxxx.onrender.com`. Точный адрес выдаёт Render: имя `dev-growth` может быть занято. Открой его по **HTTPS**. Должна появиться форма входа; введи `Eremeev-SA` и пароль из переменной Render.

Адрес Render автоматически используется для защиты запросов. Если вход возвращает «Запрос с другого сайта запрещён», проверь **Environment → APP_ORIGIN**: если переменная создана вручную, она должна совпадать с адресом в браузере, включая `https://`, без завершающего `/`. Для обычного адреса Render удали неверную `APP_ORIGIN` и перевыложи сервис — будет использована `RENDER_EXTERNAL_URL`.

## 6. Проверь приватность и общую базу

1. Открой сайт в **инкогнито**: без входа видна только форма.
2. Там же открой `https://ТВОЙ-АДРЕС/api/state`: ожидается сообщение «Войди в свой профиль» и HTTP 401.
3. Открой `https://ТВОЙ-АДРЕС/data/roadmap.json`: браузер должен перенаправить на форму входа.
4. В обычном браузере отметь одну задачу и дождись **«Сохранено на сервере»**.
5. Войди на телефоне с теми же данными — отметка должна быть видна. После изменений обновляй уже открытую страницу другого устройства.
6. Нажми **Выйти**: обновление и прямые ссылки снова требуют входа.

Регистрации нет, профиль всего один. Если кто-то знает твой пароль, он тоже сможет войти в этот профиль — не передавай его.

## 7. Перенеси прогресс и выключи GitHub Pages

На новом сайте: **Настройки → Импортировать базу → выбрать сохранённый progress.sqlite → подтвердить**. Проверь отметки и заметки.

Теперь GitHub → репозиторий → **Settings → Pages** → меню публикации **⋯ → Unpublish site** (в зависимости от интерфейса кнопка Unpublish может быть видна сразу). Подтверди отключение. Workflow публикации Pages из новой версии удалён, но уже опубликованный старый сайт от этого не исчезает.

Подожди обновления GitHub Pages и открой старый адрес в инкогнито: учебный сайт больше не должен открываться. После этого пользуйся только новым адресом Render. Адрес `eremeev-sa.github.io/dev-growth/` не может обслуживать сервер Render сам по себе. Для собственного домена настрой **Render → Settings → Custom Domains** и укажи его точный HTTPS-адрес в `APP_ORIGIN`, затем перевыложи сервис.

## 8. Дальнейшее использование

- **Изменить пароль:** Render → сервис → Environment → изменить `OWNER_PASSWORD` → Save and deploy. Все предыдущие сессии будут отозваны, прогресс сохранится.
- **Обновить сайт:** изменения в `main` запустят проверку GitHub и автоматический deploy Render, если Auto Deploy включён. Постоянный диск сохраняется.
- **Сделать копию:** сайт → Настройки → Скачать progress.sqlite. Храни файл приватно. Делай это до удаления/переноса сервиса или диска.
- **Проверить ошибки:** Render → Events / Logs. Если нет `OWNER_PASSWORD` или диск смонтирован неверно, исправь Environment / Disks и выполни Deploy latest commit.
- **Напоминания MAX:** в GitHub Actions Variables укажи `LEARNING_SITE_URL` с новым HTTPS-адресом. Затем настрой бота по README. Без этого не включай напоминания со ссылкой `auto`.

Не удаляй постоянный диск и не включай несколько экземпляров: здесь один сервер и одна SQLite. Доступ к Render и GitHub также оставь только у себя.
