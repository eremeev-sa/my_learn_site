# Бесплатный запуск: Cloudflare Workers + D1

Один профиль, серверная проверка входа, одна постоянная SQLite. Нужны бесплатные аккаунты Cloudflare и GitHub; свой домен и платный сервер не требуются. **Тариф выбирай Workers Free.** Подготовленный код ещё не означает, что сайт уже опубликован.

## 1. Сохрани старый прогресс

В старом браузерном сайте открой **Настройки → Скачать progress.sqlite**. Не выключай Pages до переноса нужных отметок. Новый хостинг не получает старые данные браузера автоматически.

## 2. Зарегистрируйся в Cloudflare

Открой **https://dash.cloudflare.com/sign-up**, создай аккаунт и подтверди email. Если предлагают добавить домен, это не нужно: выбери **Workers & Pages / Build applications / Compute**. Для этой схемы достаточно **Workers Free**. Не включай Workers Paid, R2 или платные дополнения: они не нужны проекту.

## 3. Создай постоянную базу D1

В меню Cloudflare открой **Storage & Databases → D1 SQL Database → Create database** (возможное короткое название — **D1**).

- Имя: **dev-growth-db**.
- Подтверди создание на бесплатном тарифе.
- Открой созданную базу и скопируй **Database ID** — строку вида UUID. Это не пароль.

Не создавай новую базу при каждом обновлении: все версии должны использовать одну и ту же D1.

## 4. Привяжи D1 к своему репозиторию

Открой **GitHub → eremeev-sa/my_learn_site → main → wrangler.jsonc → карандаш Edit**. Если ты уже переименовал репозиторий, открывай его под новым именем.

Найди объект в `d1_databases` и добавь **одну строку** `database_id` с твоим Database ID. Получится:

```json
"d1_databases": [
  {
    "binding": "DB",
    "database_name": "dev-growth-db",
    "database_id": "ВСТАВЬ-СЮДА-DATABASE-ID",
    "migrations_dir": "migrations"
  }
]
```

Заменяется именно строка-пример, кавычки и запятые сохрани. Нажми **Commit changes → Commit directly to main**. Остальные настройки не меняй: `run_worker_first: true` нужен для защиты файлов. Реальный пароль сюда не добавляется.

## 5. Подключи тот же GitHub-репозиторий к Workers

Cloudflare → **Workers & Pages → Create application → Import a repository / Continue with GitHub**. Нужен **Worker**, а не отдельный статический Pages-сайт.

1. Разреши Cloudflare доступ к своему репозиторию. Второй репозиторий создавать не надо.
2. Выбери репозиторий и ветку **main**.
3. Имя Worker: **dev-growth** — оно должно совпадать с `name` в `wrangler.jsonc`.
4. Root directory: корень репозитория (оставь пустым).
5. Build command: **`npm run build`**.
6. Deploy command: **`npm run deploy`**. Если предлагают команду для preview/non-production, отключи такие ветки/preview для личного кабинета.
7. Нажми **Deploy**.

Зависимости ставятся из `package-lock.json`. Команда deploy применит миграцию к **DB**, затем загрузит сервер и файлы. Миграция создаёт таблицы, не удаляя сохранённый прогресс.

Если выводится `database_id is required`, проверь шаг 4 и что сборка использует последний коммит main. Если ошибка `no such table`, значит не выполнилась миграция: проверь Deploy command. При ошибке прав D1 в **Settings → Builds → API token** проверь, что токен сборки имеет доступ **Account → D1 → Edit** к этому аккаунту; Cloudflare описывает нужный доступ в ошибке сборки. Не публикуй сам токен в коде или переписке.

## 6. Задай пароль в закрытых настройках Worker

Открой созданный **dev-growth → Settings → Variables and Secrets → Add**. Важно: это настройки работающего Worker, не только переменные Build.

Добавь оба значения с типом **Secret**:

| Имя | Что ввести |
| --- | --- |
| `OWNER_PASSWORD` | Твой пароль для входа, 12–200 символов. Можно ранее выбранный. |
| `SESSION_SECRET` | Другая случайная строка 32–200 символов, например из генератора менеджера паролей. Это технический ключ, вводить его в форму входа не нужно. |

Логин уже задан: **Eremeev-SA** (`OWNER_USERNAME`). Пароль и технический секрет не нужно отправлять в GitHub или присылать мне. Нажми **Save and Deploy / Deploy**, чтобы новые значения применились.

До настройки секретов посетители могут увидеть только форму входа; войти и получить план/прогресс невозможно. Примеры `replace-...` из `.dev.vars.example` сервер специально не принимает. Не заменяй секреты этими примерами.

## 7. Открой и проверь

После успешного deploy в разделе **Domains & Routes** будет адрес вида **https://dev-growth.ТВОЙ-ПОДДОМЕН.workers.dev**. Cloudflare может попросить выбрать поддомен workers.dev — это бесплатный адрес, покупать домен не нужно.

1. Открой адрес по HTTPS и войди: **Eremeev-SA + OWNER_PASSWORD**.
2. Отметь задачу, дождись **«Сохранено на сервере»**, обнови страницу — отметка должна остаться.
3. Войди на телефоне — профиль и отметка те же. После изменений обновляй уже открытую страницу другого устройства.
4. В инкогнито без входа видна только форма. `https://ТВОЙ-АДРЕС/api/state` должен вернуть HTTP 401, а `/data/roadmap.json` — перенаправить на вход.
5. Нажми **Выйти**: доступ снова закрыт.

Регистрации для других людей нет. Любой, кому известен пароль, сможет войти в этот же профиль, поэтому пароль остаётся только у тебя.

## 8. Перенеси отметки и отключи старый публичный сайт

Новый сайт → **Настройки → Импортировать базу → сохранённый progress.sqlite → подтвердить**. Проверь заметки и отметки. Это заменяет общую учёбу на всех устройствах; пароль не меняется.

После этого GitHub → репозиторий → **Settings → Pages → ⋯ → Unpublish site**. Подожди обновления и проверь старый URL в инкогнито. Удаление workflow само по себе не выключает старый сайт. Прежний адрес `eremeev-sa.github.io/...` не заменяется на Worker автоматически — пользуйся новым workers.dev.

Если на Render уже появились платные ресурсы, после сохранения данных удали их в Render и проверь Billing. Отмена окна добавления карты обычно не создаёт оплачиваемый сервис, но состояние своего аккаунта нужно проверить в Render.

## Лимиты и обслуживание

Workers Free: **100 000 запросов в день**. Все файлы проходят проверку Worker и тоже считаются запросами. D1 Free: **5 млн прочитанных строк, 100 000 записанных строк в день и 5 ГБ суммарного хранения**. Лимиты общие для аккаунта. Для одного учебного профиля обычно достаточно; бесплатный тариф не включает автоматическое списание за превышение — запросы/операции могут перестать выполняться до сброса квоты. Не переключай аккаунт на Paid, если хочешь оставаться на бесплатной схеме.

- Раз в неделю **Настройки → Скачать progress.sqlite**. Код GitHub не содержит личный прогресс.
- Изменения main автоматически выкладываются через Workers Builds, если интеграция включена. D1 и секреты сохраняй прежними.
- Для смены пароля: Worker → Settings → Variables and Secrets → изменить `OWNER_PASSWORD` → Deploy. Старые сессии перестанут действовать, прогресс останется. Смена `SESSION_SECRET` также отзывает входы.
- MAX: в GitHub Actions Variables поставь `LEARNING_SITE_URL` равным новому HTTPS-адресу. Настройка бота описана в README; реальная отправка отдельно не проверялась.
- Не удаляй D1 и не публикуй `dist/` отдельно на Pages: первая операция удалит прогресс, вторая раздаст файлы без серверной проверки.

Официальные источники: [Workers Free](https://developers.cloudflare.com/workers/platform/pricing/), [D1 Free](https://developers.cloudflare.com/d1/platform/pricing/), [подключение GitHub](https://developers.cloudflare.com/workers/ci-cd/builds/), [миграции D1](https://developers.cloudflare.com/d1/reference/migrations/), [проверка доступа перед файлами](https://developers.cloudflare.com/workers/static-assets/routing/worker-script/).

## Вариант без ручного Database ID

Для публичного репозитория доступен [официальный Deploy to Cloudflare](https://deploy.workers.cloudflare.com/?url=https://github.com/eremeev-sa/my_learn_site): он создаёт копию репозитория в твоём GitHub и автоматически настраивает D1. Это альтернативный путь, **не выполняй его после шагов 3–6 для того же сайта**. Он удобнее, но для сохранения одного исходного репозитория используй основные шаги выше. Оба секрета всё равно задаются приватно. После развёртывания через копию дальнейшие изменения нужно делать в подключённой копии; push в исходный репозиторий её не обновит.
