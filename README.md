# Dev Growth — личный учебный кабинет

HTML + CSS + JavaScript, небольшой сервер Node.js и одна общая SQLite. **Один аккаунт владельца, регистрации нет.** Сервер проверяет доступ к страницам, учебным файлам и API. Код остаётся в одном GitHub-репозитории. Для размещения используется Render с постоянным диском; GitHub Pages для этой версии не подходит.

## Развернуть без опыта

Следуй [пошаговой инструкции Render](docs/RENDER.md). Понадобятся аккаунт Render, подключение GitHub-репозитория и платный Web Service с постоянным диском. `render.yaml` уже описывает нужные настройки. Реальный пароль вводится только в закрытой переменной Render `OWNER_PASSWORD`; в репозитории его нет.

Новый адрес выдаст Render, например `https://dev-growth-….onrender.com`. Адрес `eremeev-sa.github.io/dev-growth/` обслуживается GitHub Pages и не может выполнять этот сервер. Свой домен можно подключить в Render позже.

**Старая публикация GitHub Pages не отключается удалением workflow.** Перед отключением скачай старый прогресс, затем после проверки нового сайта выбери GitHub → Settings → Pages → Unpublish site (подробности в инструкции). До этого старый сайт остаётся публичным.

## Что сохраняется

- План с **19 октября 2026 года**, 52 недели и 260 задач; несколько видео YouTube на выбор в каждой неделе.
- Современный интерфейс, светлая/тёмная тема, пошаговый раздел «С чего начать», подсказки к первой неделе.
- Отметки, заметки, избранное, расписание и настройки — общие для телефона и компьютера после входа.
- Экспорт/импорт файла `.sqlite`, календарь с напоминаниями и необязательный MAX.

Открытая страница загружает состояние при входе/обновлении. После работы на другом устройстве обнови страницу. Сервер проверяет номер версии при записи: устаревшая вкладка получает ошибку вместо перезаписи нового прогресса. Это не совместное редактирование в реальном времени. Интернет нужен для сохранения.

## Вход и приватность

Сервер при запуске создаёт/обновляет **единственную** запись `owner` из `OWNER_USERNAME` и `OWNER_PASSWORD`. Пароль хранится в приватной SQLite как scrypt-хеш со случайной солью. Смена переменных и перезапуск меняют вход и отзывают все сессии, сохраняя учёбу. Посетители не могут создать или заменить аккаунт через сайт.

Сессии действуют 12 часов. В браузере находится случайная `HttpOnly; SameSite=Strict` cookie, в production также `Secure`; на сервере — только её SHA-256. «Выйти» удаляет сессию на сервере. Нужен HTTPS: его предоставляет Render. Запросы записи требуют совпадающий Origin. После восьми неудачных входов проверка блокируется на 15 минут; лимит сохраняется при перезапуске.

Файл `DATA_DIR/private.sqlite` содержит таблицы `owner`, `sessions`, `attempts`, `revision`, `progress`, `notes`, `settings`. Он не раздаётся HTTP-сервером и не добавляется в Git. Фронтенд использует sql.js для работы с учебными данными в памяти и экспорта `.sqlite`; учётные данные и сессии в экспорт не входят. Старые резервные копии импортируют только учёбу. Публичный репозиторий по-прежнему раскрывает исходный код и типовой учебный план; личный прогресс остаётся на сервере.

## Запуск на своём компьютере

Установи **Node.js 24 LTS**. Скачай репозиторий и открой терминал в его папке.

1. Скопируй `.env.example` в `.env` (можно через Проводник/редактор).
2. В `.env` укажи свои `OWNER_USERNAME` и `OWNER_PASSWORD` (12–200 символов). Файл `.env` не отправляй в GitHub.
3. Выполни `npm start`.
4. Открой **http://127.0.0.1:8080** и войди. В локальном режиме используй именно этот адрес, соответствующий `APP_ORIGIN`.

Ничего устанавливать через npm не нужно: сервер использует встроенную SQLite Node.js, sql.js уже лежит в `assets/vendor/`. Для проверки: `npm test` и `npm run build`. `build` проверяет исходники и обязательные файлы; сервер запускается из репозитория. Открытие `index.html` двойным кликом или через Python HTTP server не запускает авторизацию.

Для другого хостинга: `NODE_ENV=production`, `DATA_DIR` на постоянном диске, `APP_ORIGIN` — точный HTTPS-адрес без завершающего `/`. На Render адрес берётся из `RENDER_EXTERNAL_URL` автоматически. Один экземпляр сервиса, без горизонтального масштабирования; SQLite находится на локальном постоянном диске этого экземпляра.

## Перенос и резервные копии

На старом сайте: Настройки → Скачать progress.sqlite. На новом: войти → Настройки → Импортировать базу → выбрать файл → подтвердить. Это заменяет учебные данные профиля на всех устройствах; логин и пароль не меняются. Старые копии могут содержать прежний локальный хеш пароля, поэтому не публикуй их.

Раз в неделю скачивай копию через настройки. Для восстановления: войти и импортировать её. Для полной серверной копии останови запись и используй штатный SQLite backup API/команду `.backup`; простое копирование `private.sqlite` работающего сервера без WAL не гарантирует целостную копию. Полная копия содержит учётные данные и сессии — храни её приватно. Удаление Render-диска уничтожает данные, даже если код сохранён в GitHub.

## Учебный прогресс

Общий счётчик = выполненные недельные задачи / 260; неделя = выполненные задачи / 5. Подготовка компьютера и этапы проекта отмечаются отдельно. Уровни 0/25/50/75/100% — ориентир прохождения плана. Первая неделя — **19–25 октября 2026 года**. Однократная миграция даты сохраняет отметки/заметки; последующие ручные изменения даты не сбрасываются.

## Напоминания без MAX

Расписание → **В календарь (.ics)**. Импортируй файл в приложение календаря и разреши уведомления там. В файл входят только строки времени `HH:MM-HH:MM`: 52 еженедельных повтора в локальном времени календаря, начиная с первого подходящего дня от даты старта, и сигнал за 10 минут. Остальные дни («Отдых», «Резерв») пропускаются. Это независимая копия расписания: после изменений удали старые серии в календаре перед повторным импортом, чтобы избежать дублей.

## Включить MAX (по желанию)

Файлы: `.github/workflows/max-reminders.yml`, `scripts/remind.js`, `data/reminders.json`. По умолчанию отправка **выключена**: без Repository Variable `MAX_REMINDERS_ENABLED=true` job не запускается.

1. Создай бота по [официальной инструкции MAX](https://dev.max.ru/docs/chatbots/bots-coding/prepare), получи токен, начни диалог с ботом или добавь его в нужный чат с правом отправки. Возможность создания бота зависит от условий платформы MAX.
2. Получи `chat_id` по [документации MAX](https://dev.max.ru/docs-api/use-cases/getting-chat-id). ID хранится строкой, чтобы не терять точность больших чисел.
3. В репозитории → **Settings → Secrets and variables → Actions → Secrets** добавь `MAX_BOT_TOKEN` и `MAX_CHAT_ID`. Не записывай токен в HTML, JS, JSON или коммиты.
4. В `data/reminders.json` установи дату старта, IANA-таймзону, адрес опубликованного сайта и занятия. Дни: 0 = воскресенье, 1 = понедельник … 6 = суббота. Время начала должно быть корректным `HH:MM`. Настройки → Скачать reminders.json выгружает текущее расписание профиля; затем вручную замени им файл в репозитории.
5. Если меняешь часы, дни или часовой пояс, измени **также cron в `.github/workflows/max-reminders.yml`**. Cron работает в UTC. По умолчанию: понедельник/четверг 21:50, суббота 15:50, воскресенье 16:50 **по Москве**, за 10 минут до сессии.
6. В **Actions → Variables → Repository variables** добавь `MAX_REMINDERS_ENABLED` со значением `true`. Workflow и расписание должны находиться в основной ветке репозитория.
7. Для проверки: **Actions → MAX learning reminders → Run workflow**. Ручной запуск отправит тестовое сообщение сразу; это реальная отправка в указанный чат. Для выключения удали переменную или поставь `false`.

Используется [POST /messages](https://dev.max.ru/docs-api/methods/POST/messages) на `https://platform-api2.max.ru` с токеном в заголовке Authorization. TLS-проверка включена; если runner сообщает об ошибке доверия сертификату, следуй актуальной документации MAX и добавь официальный доверенный CA через `NODE_EXTRA_CA_CERTS`. Не отключай проверку TLS.

Actions может задерживать или пропускать запуски; напоминание отправляется в течение 30 минут от планового момента, затем пропускается. Это не будильник с гарантированной доставкой. В публичных репозиториях GitHub может отключить scheduled workflows после 60 дней отсутствия активности; проверяй статус Actions. Ручной повтор workflow может повторно отправить сообщение: постоянной серверной дедупликации нет. По расписанию отправка ограничена 52 неделями, ручная проверка доступна и вне срока. GitHub не видит серверную SQLite-базу, поэтому выполненные задачи не отключают напоминания. Сайт сам не отправляет токены и не синхронизирует настройки с репозиторием.

## Источники и границы

Учебные этапы, исходные ресурсы, расписание, soft skills и проект перенесены из приложенных PDF и `roadmap_content.json` версии 1.0 от 16.10.2026. PDF был прочитан как текст; структурированные сущности взяты из JSON. Android-промпт — справочный документ прежней задумки, его инструкции о Kotlin/Compose/Room к этому сайту не применяются.

**52 отдельных недель в исходнике нет**: недельные названия, задания и распределение тем — добавленная детализация исходных этапов. Дополнительные YouTube-ссылки найдены веб-поиском 18.10.2026; воспроизведение не проверялось. Старые курсы могут показывать неактуальные версии .NET или другую СУБД; это подписано в карточках. Выбирай релевантный раздел на 15–45 минут, а актуальные API проверяй по официальным материалам. Исходные URL сохранены в библиотеке; Android-справочники сохранены в JSON, но скрыты из учебной библиотеки как не относящиеся к новой реализации.

Проверки `npm test`: расчёт прогресса, границы недель, целостность всех 52 недель, ссылки на ресурсы, SQLite round-trip, экспорт/импорт, откат при ошибке сохранения, игнорирование импортированных триггеров, календарь и временные окна напоминаний. Реальная отправка MAX требует настроенного бота и отдельно не выполнялась.

Сторонний компонент: sql.js 1.13.0 и его лицензия находятся в `assets/vendor/SQLJS-LICENSE.txt`; [исходный проект](https://github.com/sql-js/sql.js).
