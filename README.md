# Dev Growth — личный учебный кабинет

HTML + CSS + JavaScript, серверная проверка входа и постоянная SQLite-база **Cloudflare D1**. Один профиль владельца, без регистрации. Компьютер и телефон используют общий прогресс. Код хранится в одном GitHub-репозитории.

## Бесплатное размещение

Основной вариант теперь **Cloudflare Workers Free + D1 Free**, а не платный Render. Пошагово: **[инструкция Cloudflare](docs/CLOUDFLARE.md)**. Можно подключить существующий репозиторий — второй репозиторий не нужен. Сервер и база уже подготовлены, но для публикации владелец должен войти в свой аккаунт Cloudflare.

На 18 октября 2026 года бесплатный Workers включает 100 000 запросов в день; D1 — 5 млн прочитанных строк и 100 000 записанных строк в день, 5 ГБ хранения суммарно в аккаунте. Это лимиты аккаунта, а не обещание безлимитной работы. Все наши файлы проходят авторизацию Worker, поэтому запросы к ним также расходуют лимит Worker. Для личного использования этого обычно достаточно. При исчерпании лимита Free операции временно перестают выполняться; платный тариф проект сам не включает.

Источники: [Workers Free](https://developers.cloudflare.com/workers/platform/pricing/), [D1 Free](https://developers.cloudflare.com/d1/platform/pricing/). Для старта Workers Cloudflare предлагает [бесплатную регистрацию без карты](https://www.cloudflare.com/products/workers/). Платный домен не нужен: сайт получит HTTPS-адрес вида `https://dev-growth.<твой-поддомен>.workers.dev`.

**GitHub Pages не выполняет серверный вход.** Старая публикация остаётся публичной, пока ты сам не выберешь Settings → Pages → Unpublish site. Сначала скачай старый прогресс, проверь новый сайт и перенеси данные, затем отключи Pages. Адрес `eremeev-sa.github.io/dev-growth/` не может сам обслуживать Cloudflare Worker.

## Что внутри

- 52 недели, 260 задач, несколько видео YouTube на выбор в каждой неделе.

## Как защищён вход

Единственный логин задан в `OWNER_USERNAME` (по умолчанию `Eremeev-SA`). `OWNER_PASSWORD` и отдельный `SESSION_SECRET` задаются только в **Cloudflare Secrets**. Реальных паролей, секретов и их проверочных значений в Git нет. Никакой регистрации или создания пользователя первым посетителем нет; без обязательных секретов вход не работает.

Cloudflare хранит секреты вне исходников. Проверка пары логин/пароль выполняется на сервере через Web Crypto HMAC-SHA-256 с отдельным секретным ключом и `crypto.subtle.verify`. Здесь не используется публичный парольный хеш или клиентская проверка. Это отличается от прежнего Node-сервера с scrypt: при переносе не копируй его приватную базу в репозиторий. Менять пароль/секрет нужно в Cloudflare, после изменения и публикации новая версия сразу отвергает прежние сессии.

Сессия — случайный токен на 12 часов в `HttpOnly; SameSite=Strict; Secure` cookie. В D1 хранится SHA-256 токена и серверная метка учётных данных. «Выйти» удаляет сессию из базы. Чтение авторизации идёт с primary D1, чтобы запаздывающая реплика не восстановила отозванный вход. После восьми проверок неверного пароля действует общий лимит на 15 минут; одновременные попытки резервируются атомарно в D1. Origin проверяется для всех запросов записи.

`assets.run_worker_first: true` обязательно: все страницы и файлы проходят сервер перед выдачей. Разрешены публично только форма входа и её JS/CSS/иконка. D1, исходники сервера, конфигурация и секреты через HTTP не раздаются. Не публикуй `dist/` отдельно на статическом хостинге: это обойдёт серверную защиту.

## База и резервные копии

В D1 три таблицы: `learning` (один снимок учебных данных и номер версии), `sessions`, `attempts`. Пароль находится в Cloudflare Secrets, а не в учебной базе. Одна атомарная операция `UPDATE ... WHERE revision=? RETURNING revision` защищает от конкурирующих записей и не переписывает сотни строк при каждом чекбоксе.

Фронтенд использует sql.js в памяти для работы с учебными таблицами и совместимого экспорта `.sqlite`. В экспорт не входят пароль, технический секрет и сессии. Файл импорта — до 8 МБ; содержащиеся в нём учебные данные в JSON — до **1,5 МБ**, чтобы помещаться в строку D1. При превышении сервер отвергает запись и сохраняет предыдущую базу.

Для переноса со старого сайта: там **Настройки → Скачать progress.sqlite**, здесь после входа **Настройки → Импортировать базу**. Импорт заменяет общую учёбу на всех устройствах, но не меняет вход. Старые копии могут содержать прежний локальный хеш — не публикуй их. Раз в неделю скачивай копию. Удаление D1 удаляет прогресс; сохранённый в GitHub код не является копией личной базы.

## Запуск на компьютере

Нужен Node.js 24 LTS. Открой терминал в папке проекта:

1. Выполни `npm ci`.
2. Скопируй `.dev.vars.example` в `.dev.vars`.
3. В `.dev.vars` замени оба примера: `OWNER_PASSWORD` — твой пароль 12–200 символов; `SESSION_SECRET` — отдельная случайная строка 32–200 символов. Примеры `replace-...` сервер намеренно не принимает.
4. Выполни `npm start` и открой `http://127.0.0.1:8080`.

Локальный запуск создаёт отдельную SQLite в `.wrangler/` через эмулятор D1; он не пишет в облачную базу. `.dev.vars`, `.env`, `.wrangler/`, `dist/` и `node_modules/` исключены из Git. Двойной клик по HTML и Python HTTP server не запускают авторизацию.

Проверки: `npm test` — серверные интеграционные тесты в настоящем workerd/Miniflare, SQLite, даты, программа и напоминания; `npm run check:worker` — сборка Worker без публикации. `npm run build` копирует только файлы интерфейса/учебный контент в `dist/`. `npm run deploy` применяет миграции и публикует Worker с этими файлами; для этого нужны личный вход Cloudflare и созданная D1.

## Учебный прогресс

Общий счётчик = выполненные недельные задачи / 260; неделя = выполненные задачи / 5. Подготовка компьютера и этапы проекта отмечаются отдельно. Уровни 0/25/50/75/100% — ориентир прохождения плана. Однократная миграция даты на 19 октября сохраняет отметки/заметки; последующие ручные изменения даты не сбрасываются.

## Напоминания без MAX

Расписание → **В календарь (.ics)**. Импортируй файл в приложение календаря и разреши уведомления там. В файл входят только строки времени `HH:MM-HH:MM`: 52 еженедельных повтора в локальном времени календаря, начиная с первого подходящего дня от даты старта, и сигнал за 10 минут. Остальные дни («Отдых», «Резерв») пропускаются. Это независимая копия расписания: после изменений удали старые серии в календаре перед повторным импортом, чтобы избежать дублей.

## Включить MAX (по желанию)

Файлы: `.github/workflows/max-reminders.yml`, `scripts/remind.js`, `data/reminders.json`. По умолчанию отправка **выключена**: без Repository Variable `MAX_REMINDERS_ENABLED=true` job не запускается.

1. Создай бота по [официальной инструкции MAX](https://dev.max.ru/docs/chatbots/bots-coding/prepare), получи токен, начни диалог с ботом или добавь его в нужный чат с правом отправки. Возможность создания бота зависит от условий платформы MAX.
2. Получи `chat_id` по [документации MAX](https://dev.max.ru/docs-api/use-cases/getting-chat-id). ID хранится строкой, чтобы не терять точность больших чисел.
3. В репозитории → **Settings → Secrets and variables → Actions → Secrets** добавь `MAX_BOT_TOKEN` и `MAX_CHAT_ID`. Не записывай токен в HTML, JS, JSON или коммиты.
4. В `data/reminders.json` установи дату старта, IANA-таймзону, адрес опубликованного сайта и занятия. Дни: 0 = воскресенье, 1 = понедельник … 6 = суббота. Время начала должно быть корректным `HH:MM`. Настройки → Скачать reminders.json выгружает текущее расписание профиля; затем вручную замени им файл в репозитории.
5. Если меняешь часы, дни или часовой пояс, измени **также cron в `.github/workflows/max-reminders.yml`**. Cron работает в UTC. По умолчанию: понедельник/четверг 21:50, суббота 15:50, воскресенье 16:50 **по Москве**, за 10 минут до сессии.
6. В **Actions → Variables → Repository variables** добавь `MAX_REMINDERS_ENABLED` со значением `true`. Workflow и расписание должны находиться в основной ветке репозитория.
7. Для проверки: **Actions → MAX learning reminders → Run workflow**. Ручной запуск отправит тестовое сообщение сразу; это реальная отправка в указанный чат. Для выключения удали переменную или поставь `false`.

Используется [POST /messages](https://dev.max.ru/docs-api/methods/POST/messages) на `https://platform-api2.max.ru` с токеном в заголовке Authorization. TLS-проверка включена; если runner сообщает об ошибке доверия сертификату, следуй актуальной документации MAX и добавь официальный доверенный CA через `NODE_EXTRA_CA_CERTS`. Не отключай проверку TLS.

Actions может задерживать или пропускать запуски; напоминание отправляется в течение 30 минут от планового момента, затем пропускается. Это не будильник с гарантированной доставкой. В публичных репозиториях GitHub может отключить scheduled workflows после 60 дней отсутствия активности; проверяй статус Actions. Ручной повтор workflow может повторно отправить сообщение: постоянной серверной дедупликации нет. По расписанию отправка ограничена 52 неделями, ручная проверка доступна и вне срока. GitHub не видит серверную SQLite-базу, поэтому выполненные задачи не отключают напоминания. Сайт сам не отправляет токены и не синхронизирует настройки с репозиторием.

## Источники и границы

Учебные этапы, исходные ресурсы, расписание, soft skills и проект перенесены из приложенных PDF и `roadmap_content.json` версии 1.0 от 16.10.2026. **52 отдельных недель в исходнике нет**: недельные названия, задания и распределение тем — добавленная детализация исходных этапов. Дополнительные YouTube-ссылки найдены веб-поиском 18.10.2026; воспроизведение не проверялось. Старые курсы могут показывать неактуальные версии .NET или другую СУБД; это подписано в карточках. Выбирай релевантный раздел на 15–45 минут, а актуальные API проверяй по официальным материалам. Исходные URL сохранены в библиотеке; Android-справочники сохранены в JSON, но скрыты из учебной библиотеки как не относящиеся к новой реализации.

Проверки `npm test`: расчёт прогресса, границы недель, целостность всех 52 недель, ссылки на ресурсы, SQLite round-trip, экспорт/импорт, откат при ошибке сохранения, игнорирование импортированных триггеров, календарь и временные окна напоминаний. Реальная отправка MAX требует настроенного бота и отдельно не выполнялась.

Сторонний компонент: sql.js 1.13.0 и его лицензия находятся в `assets/vendor/SQLJS-LICENSE.txt`; [исходный проект](https://github.com/sql-js/sql.js).
