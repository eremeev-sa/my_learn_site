# Dev Growth — личная дорожная карта

Рабочий сайт на **HTML + CSS + JavaScript и SQLite** для изучения C#/.NET, PostgreSQL и AI. Одна папка, один GitHub-репозиторий; сервер и платный хостинг не нужны.

## Что внутри

- 52 недели, 260 задач: основной трек, AI, Developer Assistant, soft skills и рефлексия.
- 20 дополнительных видеоресурсов; у каждой недели минимум три ссылки YouTube на выбор. Это тематические курсы и разборы, некоторые повторяются по неделям. Для узких тем доступны поиск YouTube и официальные материалы этапа. Смотреть все видео не нужно.
- Чекбоксы, заметки, общий и недельный прогресс, прогресс этапов, пять уровней.
- Полные цели, темы, практика, результаты и критерии исходных этапов; библиотека с поиском и избранным.
- Редактируемое расписание, экспорт календаря с напоминаниями, светлая/тёмная тема.
- Экспорт и импорт настоящего файла `.sqlite`.
- Необязательные напоминания в MAX через GitHub Actions.

## Развернуть на GitHub Pages

1. Помести все файлы проекта в один репозиторий, включая скрытую папку `.github`. Основная ветка в workflow называется `main`; если твоя ветка называется иначе, измени `.github/workflows/pages.yml`.
2. Открой репозиторий → **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Открой **Actions → Deploy learning site to GitHub Pages → Run workflow**, выбери ветку `main`. В дальнейшем push в `main` запускает публикацию автоматически.
4. После успешного workflow ссылка будет в **Settings → Pages** и в **Environments → github-pages**. Для этого репозитория ожидаемый адрес: `https://eremeev-sa.github.io/my_learn_site/`. Само наличие адреса в README не означает, что сайт опубликован.

Сначала проверь доступность Pages для своего тарифа и видимости репозитория. Если Actions отключены, разреши их в Settings → Actions. База пользователя не публикуется — на Pages отправляются только статические файлы и пустая начальная база.

Можно обойтись без Actions: в Settings → Pages выбери **Deploy from a branch → main → / (root)**. `index.html` лежит в корне; сборка не нужна. В таком случае отключи workflow `Deploy learning site to GitHub Pages`, чтобы не было двух способов публикации.

## Запустить локально

Нужен Python 3. Из папки репозитория:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Открой `http://localhost:8080`. На Windows команда может называться `py -m http.server 8080 --bind 127.0.0.1`. Двойной клик по `index.html` через `file://` не подходит: нужен HTTP для загрузки JSON, модулей и WebAssembly.

Для проверки и сборки нужен Node.js 22+:

```sh
npm test
npm run build
```

`npm install` не нужен: runtime-зависимости уже находятся в `assets/vendor/`. Сборка лишь копирует `index.html`, `assets/` и `data/` в `dist/`.

## Как работает SQLite

GitHub Pages не исполняет серверный код и не принимает записи в общий файл базы. Здесь используется **sql.js 1.13.0** — SQLite в WebAssembly. При первом запуске загружается `data/progress.sqlite`; затем после каждого изменения база сохраняется в **IndexedDB браузера**.

Таблицы: `app_meta` (версия формата), `progress` (ID и дата завершения), `notes` (недельные заметки), `settings` (дата старта, расписание, тема, избранное). Контент отдельно в `data/roadmap.json`. Изменение сохраняется только после успешной записи IndexedDB; при ошибке состояние откатывается, приложение показывает сообщение.

Это личный трекер одного устройства. **Автоматической синхронизации между компьютером и телефоном нет.** Для переноса: Настройки → Скачать progress.sqlite → на другом устройстве Импортировать базу. Импорт заменяет текущие данные после подтверждения. Данные не отправляются на GitHub и не доступны другим посетителям сайта. Очистка данных сайта, приватный режим и смена браузера могут привести к потере локального прогресса — регулярно скачивай копии.

Web Locks защищает базу от одновременной записи в нескольких вкладках одного сайта; в браузере без Web Locks используй одну вкладку. При первом запуске дата начала — понедельник текущей недели; её можно изменить в настройках. Приложение открывает выбранную неделю, иначе текущую по дате старта. Интернет нужен для первого открытия сайта и внешних видео; полноценный offline-кеш не заявлен.

Общий прогресс = выполненные недельные задачи / **260**. Прогресс недели = выполненные задачи / 5. Этап = выполненные недельные задачи с его `phase` / все связанные задачи. Отметки этапов проекта считаются отдельно. Просмотр ссылки не отмечает задачу выполненной. Уровни меняются на 0/25/50/75/100% и служат ориентиром прохождения плана, а не подтверждением профессиональной квалификации.

## Напоминания без MAX

Расписание → **В календарь (.ics)**. Импортируй файл в приложение календаря и разреши уведомления там. В файл входят только строки времени `HH:MM-HH:MM`: 52 еженедельных повтора в локальном времени календаря, начиная с первого подходящего дня от даты старта, и сигнал за 10 минут. Остальные дни («Отдых», «Резерв») пропускаются. Это независимая копия расписания: после изменений удали старые серии в календаре перед повторным импортом, чтобы избежать дублей.

## Включить MAX (по желанию)

Файлы: `.github/workflows/max-reminders.yml`, `scripts/remind.js`, `data/reminders.json`. По умолчанию отправка **выключена**: без Repository Variable `MAX_REMINDERS_ENABLED=true` job не запускается.

1. Создай бота по [официальной инструкции MAX](https://dev.max.ru/docs/chatbots/bots-coding/prepare), получи токен, начни диалог с ботом или добавь его в нужный чат с правом отправки. Возможность создания бота зависит от условий платформы MAX.
2. Получи `chat_id` по [документации MAX](https://dev.max.ru/docs-api/use-cases/getting-chat-id). ID хранится строкой, чтобы не терять точность больших чисел.
3. В репозитории → **Settings → Secrets and variables → Actions → Secrets** добавь `MAX_BOT_TOKEN` и `MAX_CHAT_ID`. Не записывай токен в HTML, JS, JSON или коммиты.
4. В `data/reminders.json` установи дату старта, IANA-таймзону, адрес опубликованного сайта и занятия. Дни: 0 = воскресенье, 1 = понедельник … 6 = суббота. Время начала должно быть корректным `HH:MM`. Настройки → Скачать reminders.json выгружает текущее браузерное расписание; затем вручную замени им файл в репозитории.
5. Если меняешь часы, дни или часовой пояс, измени **также cron в `.github/workflows/max-reminders.yml`**. Cron работает в UTC. По умолчанию: понедельник/четверг 21:50, суббота 15:50, воскресенье 16:50 **по Москве**, за 10 минут до сессии.
6. В **Actions → Variables → Repository variables** добавь `MAX_REMINDERS_ENABLED` со значением `true`. Workflow и расписание должны находиться в основной ветке репозитория.
7. Для проверки: **Actions → MAX learning reminders → Run workflow**. Ручной запуск отправит тестовое сообщение сразу; это реальная отправка в указанный чат. Для выключения удали переменную или поставь `false`.

Используется [POST /messages](https://dev.max.ru/docs-api/methods/POST/messages) на `https://platform-api2.max.ru` с токеном в заголовке Authorization. TLS-проверка включена; если runner сообщает об ошибке доверия сертификату, следуй актуальной документации MAX и добавь официальный доверенный CA через `NODE_EXTRA_CA_CERTS`. Не отключай проверку TLS.

Actions может задерживать или пропускать запуски; напоминание отправляется в течение 30 минут от планового момента, затем пропускается. Это не будильник с гарантированной доставкой. В публичных репозиториях GitHub может отключить scheduled workflows после 60 дней отсутствия активности; проверяй статус Actions. Ручной повтор workflow может повторно отправить сообщение: постоянной серверной дедупликации нет. По расписанию отправка ограничена 52 неделями, ручная проверка доступна и вне срока. GitHub не видит локальную SQLite-базу, поэтому выполненные задачи не отключают напоминания. Сайт сам не отправляет токены и не синхронизирует настройки с репозиторием.

## Источники и границы

Учебные этапы, исходные ресурсы, расписание, soft skills и проект перенесены из приложенных PDF и `roadmap_content.json` версии 1.0 от 16.10.2026. PDF был прочитан как текст; структурированные сущности взяты из JSON. Android-промпт — справочный документ прежней задумки, его инструкции о Kotlin/Compose/Room к этому сайту не применяются.

**52 отдельных недель в исходнике нет**: недельные названия, задания и распределение тем — добавленная детализация исходных этапов. Дополнительные YouTube-ссылки найдены веб-поиском 18.10.2026; воспроизведение не проверялось. Старые курсы могут показывать неактуальные версии .NET или другую СУБД; это подписано в карточках. Выбирай релевантный раздел на 15–45 минут, а актуальные API проверяй по официальным материалам. Исходные URL сохранены в библиотеке; Android-справочники сохранены в JSON, но скрыты из учебной библиотеки как не относящиеся к новой реализации.

Проверки `npm test`: расчёт прогресса, границы недель, целостность всех 52 недель, ссылки на ресурсы, SQLite round-trip, экспорт/импорт, откат при ошибке сохранения, игнорирование импортированных триггеров, календарь и временные окна напоминаний. Реальная отправка MAX требует настроенного бота и отдельно не выполнялась.

Сторонний компонент: sql.js 1.13.0 и его лицензия находятся в `assets/vendor/SQLJS-LICENSE.txt`; [исходный проект](https://github.com/sql-js/sql.js).
